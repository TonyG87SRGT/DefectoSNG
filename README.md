# DefectoSNG

Устанавливаемый PWA-справочник с двумя основными задачами: визуально распознать дефект по атласу и открыть применимый критерий отбраковки. Приложение не требует сборки: интерфейс написан на HTML, CSS и ES-модулях, данные хранятся локально в JSON и доступны офлайн.

## Что входит в продукт

- восемь визуальных коллекций: дефекты сварных соединений, основной металл, фрактография, радиографические и капиллярные индикации, эхо-сигналы УЗК, неисправности машин и спектры вибрации;
- 202 нормативных критерия по 11 веткам НТД;
- прямой переход из визуальной карточки к найденным критериям;
- единый поиск одновременно по атласу и критериям;
- избранные визуальные карточки;
- адаптивный мобильный интерфейс и PWA-кэш.

Визуальное сходство само по себе не является решением о годности. Критерий применяется после выбора объекта, нормативного документа, метода и условий контроля.

## Локальный запуск

Для ES-модулей и Service Worker нужен HTTP-сервер:

```bash
npm ci
npm run serve
```

Откройте `http://127.0.0.1:4173/`.

Проверки:

```bash
npm run check
npm run test:e2e
```

Для первого запуска Playwright может потребоваться `npx playwright install chromium`.

## Структура

- `index.html` — оболочка, строка поиска и нижняя навигация.
- `css/focused.css` — компоновка упрощённого интерфейса; остальные подключаемые стили отвечают за базовую тему, карточки, критерии и PWA.
- `js/app.js`, `js/router.js`, `js/views.js` — запуск, маршруты и экраны.
- `js/store.js` — загрузка визуальных коллекций и построение их дерева.
- `js/criterionLinks.js` — связь визуальных признаков с критериями.
- `js/criteria.js`, `js/criteriaEngine.js` — интерфейс и расчёты критериев.
- `js/search.js`, `js/favorites.js` — единый поиск и избранное.
- `data/vik.json`, `data/uzk.json`, `data/pvk.json`, `data/rk.json`, `data/vibration.json` — только визуальные коллекции.
- `data/criteria.json` — нормативная модель критериев; значения не смешиваются с содержимым атласов.
- `js/pwaConfig.js`, `sw.js` — версия и полный перечень офлайн-ресурсов.
- `scripts/validate-project.mjs` — проверка ID, дерева, изображений, нормативной модели и PWA-кэша.
- `tests/`, `e2e/` — модульные и браузерные проверки.

## Добавление визуальной карточки

1. Добавьте карточку в файл нужного метода и свяжите её с одной из корневых коллекций через `parentId`.
2. Используйте глобально уникальный `id`, непустой `title` и относительные пути к изображениям.
3. Для фотографии, схемы или диагностического изображения используйте `atlas`, `mediaSlots` либо поддерживаемую секцию изображения.
4. Добавьте синонимы и точное название дефекта: они участвуют в поиске и связи с критериями.
5. Включите новый локальный ресурс в `OPTIONAL_APP_PATHS` файла `js/pwaConfig.js`.
6. Выполните `npm run check` и мобильный браузерный сценарий.

Нормативные значения, формулы и области применения изменяются отдельно и только после сверки с первичным источником.

## Публикация

Production-конфигурация, резервные копии и восстановление описаны в [`docs/operations.md`](docs/operations.md). Публичный web-root не должен содержать Git metadata, тесты, логи или внутреннюю документацию.

Для выпуска синхронно обновите версии в `package.json`, `package-lock.json`, `manifest.json`, `js/pwaConfig.js` и `sw.js`, дополните `CHANGELOG.md`, выполните `npm run check` и `npm run test:e2e`, затем опубликуйте проверенный коммит через защищённую основную ветку.
