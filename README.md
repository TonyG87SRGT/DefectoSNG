# DefectoSNG

Карманный PWA-справочник по неразрушающему контролю. Приложение не требует сборки: интерфейс написан на HTML, CSS и ES-модулях, а материалы хранятся в JSON.

## Локальный запуск

Для работы ES-модулей и Service Worker открывайте проект через HTTP-сервер, а не напрямую с диска.

```bash
python -m http.server 8000
```

После запуска откройте `http://localhost:8000/`. Если сервер запущен уровнем выше каталога проекта, добавьте имя каталога к адресу.

Для проверки данных и модульных тестов нужен Node.js 22 или новее:

```bash
npm install
npm run check
```

Полный браузерный smoke-test запускается отдельно:

```bash
npx playwright install chromium
npm run test:e2e
```

## Структура проекта

- `index.html` — оболочка приложения и нижняя навигация.
- `css/style.css` — точка подключения CSS-модулей; `base`, статьи, избранное, инструменты, PWA и атлас разнесены по отдельным файлам.
- `js/app.js` — запуск приложения и выбор экрана для текущего маршрута.
- `js/router.js` — hash-маршруты и история переходов.
- `js/store.js` — загрузка данных и доступ к материалам.
- `js/config.js`, `js/schema.js` — общая конфигурация и проверяемая схема данных.
- `js/renderers.js`, `js/articleNavigation.js` — рендеринг секций и якорное содержание длинных статей ВИК.
- `js/search.js`, `js/searchCore.js`, `js/favorites.js`, `js/atlas.js` — поиск, избранное и атлас.
- `js/pipelineJoints.js`, `data/pipeline-welded-joints.json`, `css/pipeline-joints.css` — атлас сварных соединений трубопроводов по ГОСТ 16037-80 и семь опубликованных справочных карточек по чтению конструкций, размерам и ВИК.
- `data/rk.json` — рабочий маршрут РК и атлас из 18 карточек радиографических индикаций.
- `data/uzk.json`, `images/uzk-echo-atlas/` — рабочий маршрут УЗК и атлас из 12 типовых картин A‑скана.
- `data/pvk.json`, `images/pvk-atlas/` — методика ПВК и атлас из 31 карточки истинных, нерелевантных и технологических индикаций; групповые обложки являются учебными иллюстрациями.
- `js/vibration.js`, `data/vibration.json`, `css/vibration.css` — обзор, группы и каталоги раздела вибродиагностики.
- `js/vibrationKnowledge.js`, `js/vibrationTaxonomy.js`, `js/vibrationRelations.js` — фасетная навигация, единый словарь тегов и автоматическая перелинковка базы знаний ВД. Будущие инструменты используют экспортируемый `vibrationKnowledgeApi`, не загружая данные повторно.
- `js/vibrationDiagnosticAssistant.js`, `js/vibrationDiagnosticQuestions.js`, `js/vibrationDiagnosticRules.js`, `js/vibrationDiagnosticEngine.js`, `js/vibrationDiagnosticStorage.js` — пошаговый офлайн-помощник по поиску вероятной неисправности, его вопросы, правила, расчёт и локальная история.
- `js/references.js`, `data/references.json` — общие справочные таблицы с локальным и глобальным поиском.
- `js/tools.js`, `js/ringWeld.js` — глобальные интерактивные инструменты; каталоги приборов и материалов находятся внутри методов контроля.
- `js/knowledgeGraph.js` — общий двусторонний граф явных связей и входящие ссылки между материалами.
- `js/pwa.js`, `js/pwaConfig.js`, `js/pwaPolicy.js`, `sw.js` — регистрация, версия и политика офлайн-режима.
- `data/*.json` — материалы по методам контроля.
- `scripts/validate-project.mjs` — проверка статусов, структуры, ID, связей, ресурсов и офлайн-кэша.
- `tests/*.test.mjs` — модульные тесты на встроенном `node:test`; `e2e/*.spec.mjs` — браузерные проверки Playwright.

## Добавление статьи

1. Выберите файл метода в `data/`: `vik.json`, `uzk.json`, `pvk.json`, `rk.json`, `vibration.json` или `pipeline-welded-joints.json`.
2. Добавьте объект с глобально уникальным строковым `id`, названием, категорией и содержимым. Поле `status` обязательно: допустимы `published` и `draft`. Черновик доступен по прямому маршруту и в своём разделе с пометкой, но не включается в глобальный поиск. Для временного исключения карточки из каталогов, поиска и автоматических связей используйте `hidden: true`; ID и прямой маршрут при этом сохраняются.
3. Для вложенной статьи укажите существующий `parentId`; для подраздела используйте `type: "section"`.
4. Содержимое статьи задаётся массивом `sections`. Поддерживаемые типы: `facts`, `text`, `steps`, `list`, `warning`, `table`, `image`, `tip`, `practice`, `note`, `comparison`, `methods`, `related`, `documents`.
5. Связанная статья задаётся объектом `{ "method": "pvk", "id": "pvk-1", "title": "Название" }`. Поле `title` проверяется на совпадение с целевой статьёй, а интерфейс получает актуальное название из хранилища.
6. Изображения кладите в `images/` и указывайте относительный путь без начального `/`.
7. Добавьте новый локальный ресурс в `ESSENTIAL_APP_PATHS` или `OPTIONAL_APP_PATHS` файла `js/pwaConfig.js`, затем выполните `npm run check`.

Неизвестный тип секции намеренно отображается в статье как ошибка. Валидатор также остановит выпуск до исправления данных.

### Структура раздела ВД

В `data/vibration.json` навигация построена как иерархия объектов `type: "section"`. На обзоре ВД показаны семь корневых направлений; вложенные тематические группы и статьи связываются через `parentId`. URL и формат избранного основаны на стабильном ID и при переносе статьи между группами не меняются. Для заготовки используйте явный `status: "draft"`, согласованный `metadata.status`, стандартный блок состояния, `futureImageLabel` и массив `futureBlocks`.

Для новой карточки ВД используйте один из шаблонов `article`, `fault`, `spectrum`, `scenario`, `reference` или `tool`. Их состав определён в `js/vibrationTemplates.js`.

Поле `metadata` содержит группу, тип материала, оборудование, неисправности, диагностические признаки, ключевые слова, ручные связи и статус. Общий поиск индексирует эти поля, а `js/vibrationRelations.js` дополняет ручные ссылки автоматическими связанными материалами.

Для будущих материалов используйте `mediaSlots` с типами `photo`, `diagram`, `spectrum`, `table` и `gallery`. Готовое изображение добавляется обычной секцией `image`, а справочные данные — секцией `table`.

Инструменты ВД дополнительно содержат `toolConfig` со `scope: "method"`: так профильные калькуляторы, помощник и журнал отличаются от глобальных инструментов приложения. Неиспользуемое диагностическое дерево удалено.

## Добавление карточки сварного соединения трубопроводов

1. Откройте `data/pipeline-welded-joints.json` и добавьте объект `article` с уникальным ID вида `pipeline-joint-c17`.
2. Укажите `parentId` категории: `pipeline-butt`, `pipeline-lap` или `pipeline-corner`.
3. В `pipelineJoint` обязательно заполните `designation`, `category`, массивы `weldingMethods`, `specialFilters`, `parameters` и объект `images`.
4. Неизвестные характеристики оставляйте `null`, а неизвестные наборы — пустыми массивами. Не добавляйте приблизительные размеры.
5. Для поиска латинского варианта добавьте обозначение вроде `C17` в `tags`.
6. Если появилась проверенная схема, укажите относительный путь в `images.edgePreparation` или `images.weldSection`; изображение должно быть оптимизировано и загружаться лениво.
7. Повышайте версию приложения и выполняйте `npm run check` перед публикацией.

## Публикация

Проект можно публиковать как статический сайт, в том числе через GitHub Pages. Все внутренние пути вычисляются относительно URL приложения, поэтому поддерживаются как корень домена, так и подпапка, например `/DefectoSNG/`.

Перед публикацией `npm run check` проверяет синтаксис, явные статусы, уникальность ID, `parentId`, связанные материалы, наличие изображений и других ресурсов, полноту PWA-кэша и автоматические тесты. Черновики не должны появляться в результатах глобального поиска.

Для полноценной установки PWA нужен HTTPS (исключение — локальный `localhost`). Сервер должен отдавать `index.html`, `manifest.json`, `sw.js`, каталоги `js`, `css`, `data`, `images` и `icons` без изменения структуры.

## Выпуск новой версии

1. Обновите версию в `package.json`.
2. Обновите `APP_VERSION` в `js/pwaConfig.js`; валидатор проверит совпадение с `package.json`.
3. Опишите изменения в `CHANGELOG.md`.
4. Выполните `npm run check`.
5. Проверьте в браузере прямые ссылки, поиск, избранное, калькулятор и обновление/offline-режим PWA.
6. После слияния создайте тег и GitHub Release. Исторические отчёты проверки хранятся в `docs/releases/`.
