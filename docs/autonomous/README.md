# Автономное развитие production DefectoSNG

Рабочая копия: `production/DefectoSNG-main` в проекте Codex `DefectoSNG`.
Основной репозиторий: `https://github.com/TonyG87SRGT/DefectoSNG.git`.
Production: `/var/www/DefectoSNG` на VPS, сайт `https://defecto-sng.ru/`.

## Обязательный порядок каждого запуска

1. Прочитать `RESUME.md`, `BACKLOG.md`, `QUALITY.md`, `DEPLOYMENTS.md` и `BACKUPS.md`.
2. Проверить лимиты Codex, Git, состояние сайта и отсутствие `.autonomous/RUN.lock`.
3. Атомарно создать собственный lock с временем и идентификатором запуска.
4. Выполнить не более одного небольшого изменения в отдельной ветке.
5. Запустить целевые тесты, полный `check`, необходимые Playwright-сценарии и независимое ревью.
6. Не публиковать при любой незавершённой обязательной проверке.
7. Перед публикацией создать новый защищённый snapshot вне `/var/www/DefectoSNG` и проверить распаковку.
8. Публиковать только воспроизводимым способом; после публикации проверить сайт, PWA и посторонние сервисы.
9. При подтверждённой регрессии восстановить предыдущий проверенный snapshot.
10. Обновить журналы и удалить только собственный lock.

Нормативные критерии, формулы и значения без отдельного подтверждения не изменяются. Каталоги `sources/`, экспериментальная копия и посторонние сервисы VPS не используются как production-источник.

## Остановка

Приостановить автоматизацию `DefectoSNG — Production Autonomous Development` в разделе Scheduled. Активный запуск отдельно не прерывается; после его окончания проверить отсутствие `.autonomous/RUN.lock`.

## Восстановление

Точный порядок находится в `RESTORE.md` каждого snapshot. Последняя подтверждённая копия указана в `BACKUPS.md`. Конфигурацию Nginx восстанавливать только после сравнения и успешного `nginx -t`.
